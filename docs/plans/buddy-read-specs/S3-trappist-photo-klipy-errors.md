## Task

Move the generic parts of Trappist's photo pipeline, KLIPY GIF client and chat error codes into `web/layers/chat/` so they can be shared, **without changing any behaviour or any Trappist word**. Read first (on the S2 branch): `web/app/data/photo.ts` (177 lines, already framework-free; `chatPhoto.ts` is a 3-line re-export of it; the Feed, the avatar face and the chat all use it), `web/app/data/klipy.ts` (244 lines), `web/app/data/chat.ts` lines ~156–252 (`RULES`, `translateChatError`, `VOICE_RULES`, `CHAT_ERROR_KEYS`), `web/app/data/result.ts` (`Loaded`, `failed`, `loaded`: German sentences), `web/layers/chat/app/types/adapter.ts` (the layer's `Result<T>`), `web/tests/chat-media.test.ts`, `web/tests/klipy.test.ts` (282 lines, recorded answers in `tests/fixtures/klipy-*.json`), `web/tests/chat-layer.test.ts`.

## Change

1. **Photo.** `web/app/data/photo.ts` → `web/layers/chat/app/utils/photo.ts` (same exports: `PHOTO_MAX_EDGE`, `GROUP_PHOTO_MAX_EDGE`, `PHOTO_MAX_BYTES`, `PHOTO_ACCEPT`, `PreparedPhoto`, `PhotoError`, `fitWithin`, `hasMetadata`, `stripJpegMetadata`, `decodeImage`, `preparePhoto`). The old path becomes a re-export (`export * from '#layers/chat/app/utils/photo'`, as `data/saveQueue.ts` does for the queue), so `data/chatPhoto.ts`, `data/avatarFace.ts`, `stores/chat.ts`, `stores/feed.ts`, `components/feed/FeedHost.vue`, `tests/chat-media.test.ts` and `e2e/chat-media.spec.ts` keep their imports. **Reword the comments** that name this app's domain (line 3: "…since the Feed's photo posts, the Feed's: owner's decision"; line 27: "`chat.photoErrors` / `feed.photoErrors` in the copy modules"): the layer's guard bans the domain words (`feed…`, `inbox`, …).
2. **KLIPY client.** `web/app/data/klipy.ts` → `web/layers/chat/app/utils/klipy.ts`, **parametrised and wordless**: `klipyUrl(key, q, page, customerId, locale)` (today `LOCALE = 'de'` is a constant), `klipyShareUrl`, `toGif`, `toPage`, `latestRequest`, `KLIPY_BASE`, `KLIPY_MEDIA_HOST`, `PAGE_SIZE`, `CONTENT_FILTER`, `MAX_QUERY`, `GifItem`, `GifPage`; `customerIdFor(memberId, salt)` (**the salt is a parameter; Trappist passes `'bookretreats-klipy:'` so every existing `customer_id` hash is unchanged**: KLIPY ranks by it); `createKlipy({ key, locale, topics, customerId, fetchImpl })` where `topics: Record<string, string | null>` maps a topic name to its search words (`null` = trending) instead of the hard-coded `GifFeed` and `TOPIC_QUERIES`, and the calls answer the layer's neutral result (`{ ok: true, value } | { ok: false, error: 'network' | 'klipy_unavailable', retryable }`) **not** a German sentence. Rename the variable `feed` (a domain word) to `topic`.
   **Trappist keeps** `data/klipy.ts` as the thin app wrapper: `GIF_FEEDS`, `GifFeed`, `TOPIC_QUERIES` (German chips), `LOCALE = 'de'`, `customerIdFor` with its salt, and a `createKlipy` that calls the layer's and converts the neutral result to `Loaded<GifPage>` with the same German sentences (`translateChatError('failed to fetch')`, `'klipy_unavailable'`) — so `stores/chat.ts`, `stores/feed.ts`, `ChatPage.vue`, `pages/feed/[id].vue` and `tests/klipy.test.ts` change **no import and no assertion**.
3. **Error codes.** New `web/layers/chat/app/utils/errors.ts`: `CHAT_ERROR_CODES` (the generic chat codes the SQL raises and the client must word: `message_conversation_unavailable`, `message_empty`, `message_too_long`, `message_reply_unavailable`, `message_rate_limited`, `message_client_id_required`, `message_client_id_reused`, `media_kind_unknown`, `media_size_invalid`, `media_path_invalid`, `media_url_invalid`, `media_missing`, `media_type_invalid`, `media_duration_invalid`, `media_peaks_invalid`, `media_too_large`, `klipy_unavailable`; **leave the phone, host and group rules out: they are this app's**) and `chatErrorCode(message: string): string | null` (the same case-insensitive "message contains code" match as `translateChatError`; also recognises the storage messages `exceeded the maximum allowed size` → `media_too_large`, `mime type` → `media_type_invalid`). **Codes only, no sentence.** Trappist's `data/chat.ts` keeps all its German sentences and `translateChatError` behaviour unchanged; add a parity test in `tests/chat-rules.test.ts` or a new `tests/chat-layer-errors.test.ts` asserting that **every layer code has a Trappist sentence** (so a code added to the package cannot go unworded).
4. **Guard and docs:** extend `web/tests/chat-layer.test.ts` with one case: no German in the layer (`/[äöüß]/i` over every layer file, comments included). `docs/plans/groups.md` "Port to BetterReads": the file table gains `photo.ts`, `klipy.ts`, `errors.ts`.
