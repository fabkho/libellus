## Task

Move the **mechanics** of Trappist's live channel into `web/layers/chat/` so that BetterReads (and any app) can use them: join one private Broadcast topic, track its status, **resync** after a rejoin and once **3 s after the first join** (the Realtime server that was idle starts streaming a moment after the join), and **replace a dead socket** after the PWA was suspended (iOS) or the device was offline. These are the bugs Trappist already paid for; they must keep working exactly as they do. Context: libellus `docs/plans/buddy-read-shared.md`, part 3 (S2) and the appendix part 1.4; this repo's `docs/plans/groups.md` "Port to BetterReads". Read first, on the S1 branch: `web/app/data/realtime.ts` (`subscribeToMember`, lines ~196–279, `COLD_START_RESYNC_MS`, `ChannelStatus`, `MemberChannel`), `web/app/stores/realtime.ts` (the Pinia store: `open`, `close`, `start`, `stop`, `revive`, `listen`, the `generation` guard, `revivedAt`), `web/tests/realtime.test.ts` (244 lines: **a stack-backed test through the real Realtime server**, not a unit test), `web/tests/chat-layer.test.ts` (the guard), `web/layers/chat/app/types/adapter.ts` (`LiveHandlers`).

## Change

1. **New `web/layers/chat/app/utils/liveChannel.ts`** (framework-free TypeScript; imports nothing from the app, no Pinia, **no `@supabase/*`** (the guard bans it): the Supabase client is injected as a small structural type).
   - Types: `ChannelStatus` (`connecting | live | reconnecting | refused | closed`), `COLD_START_RESYNC_MS = 3_000`, `ChannelLike` (`on('broadcast', { event: '*' }, cb)` and `subscribe(cb(state, error))`, both returning the channel), **`RealtimeLike`** = `{ setAuth(): PromiseLike<unknown>; channel(topic: string, opts: { config: { private: boolean } }): ChannelLike; removeChannel(channel: ChannelLike): PromiseLike<unknown> }`. This is exactly what BetterReads' lazily loaded Realtime client offers (`libellus web/app/data/importJobFeed.ts`: `setAuth`, `channel`, `removeChannel`); Trappist adapts its supabase-js client in three lines (`client.realtime.setAuth()` lives on `client.realtime`, so a small adapter object, not the client itself).
   - `subscribeTopic<E>(client: RealtimeLike, topic: string, parse: (event: string, payload: unknown) => E | null, handlers: { onEvent(e: E): void; onStatus?(s: ChannelStatus): void; onResync?(reason: 'rejoin' | 'coldStart'): void }): { ready: Promise<boolean>; status(): ChannelStatus; unsubscribe(): Promise<void> }`: **the body of `subscribeToMember`, unchanged in behaviour** (private channel, `setAuth` before the first join, `SUBSCRIBED` → `live` and `rejoin` resync or the cold-start timer, `CHANNEL_ERROR` with `unauthori[sz]ed|permission` → `refused` and no retry, other errors/`TIMED_OUT`/`CLOSED` → `connecting`/`reconnecting`, `unsubscribe` clears the timer and removes the channel).
   - `createLiveConnection<E extends { type: string }>(options)`: the **store's mechanics without Pinia and without `window`**: one channel per signed-in device; `start(id)` (harmless when already hers and alive), `stop()`, `status`, `memberId`, `online`; a `generation` guard so callbacks of an older channel are ignored; `close()` resolves when the channel is gone (supabase-js hands back the same channel for the same topic while the old one is still there, so a new join waits for the leave); **`revive()`**: when `online` returns or the page becomes visible after more than 2 s away, or the status is not `live`: if `live`, emit `resync`; otherwise replace the channel (one revival at a time) and, once it is live, emit `resync` and remember `revivedAt` so that channel's own cold-start resync (within `COLD_START_RESYNC_MS + 2_000`) is not emitted a second time (the database's load, r10). Inject what it needs: `open(id, handlers)` (returns a channel or null), `now()`, and an `env` with `isOnline()` and a `listen({ online, offline, hidden, visible })` registration, so Node tests drive it with fakes. Events are emitted through a small typed emitter (`on(type, handler)` returning the unsubscribe; one failing listener does not stop the others) that also carries the pseudo-event `{ type: 'resync' }`.
2. **Trappist keeps its own event union and Pinia store, now thin over the core:** `web/app/data/realtime.ts` keeps `RealtimeEvent`, `toRealtimeEvent`, `memberTopic`, its Feed/connection/chapter events and **the same exported names** (`subscribeToMember(client, memberId, handlers)`, `COLD_START_RESYNC_MS`, `ChannelStatus`, `MemberChannel`, `MemberChannelHandlers`): `subscribeToMember` becomes `subscribeTopic(adaptClient(client), memberTopic(id), toRealtimeEvent, handlers)`. `web/app/stores/realtime.ts` keeps its `LiveEvents` types, its refs (`status`, `memberId`, `online`) and its public API (`on`, `start`, `stop`) and delegates to `createLiveConnection` with the browser env (`navigator.onLine`, `window` online/offline, `document.visibilitychange`). No caller changes (`plugins/realtime.client.ts`, the chat and inbox stores, `tests/realtime.test.ts`).
3. **Guard and docs:** `web/tests/chat-layer.test.ts` gets nothing to list (it guards new files by itself), but add one case: the layer imports no `@supabase/realtime-js` and no `@supabase/*` (already covered by `banned`; assert it for `liveChannel.ts` by name). `web/AGENTS.md` (the chat layer's rules): one line, "the layer's live channel takes the client as an injected `RealtimeLike`; it never imports realtime-js". `docs/plans/groups.md` "Port to BetterReads": the layer's file table gains `liveChannel.ts`.

## Tests

- **New `web/tests/chat-layer-live.test.ts`**, plain Node (the `unit` project: it must not import `tests/support/*`; fake `RealtimeLike`, fake channel, `vi.useFakeTimers()`, fake env): first join → `live`, **one** cold-start `coldStart` resync after exactly 3 s and none if no longer live; a rejoin (`SUBSCRIBED` again after `CLOSED`/`CHANNEL_ERROR`) → `rejoin` resync, no second cold-start timer; an `unauthorized` error → `refused`, the channel removed, no retry, `ready` resolves false; `TIMED_OUT` before ever live → `connecting`, after live → `reconnecting`; `unsubscribe` clears the timer and removes the channel once; `parse` returning null drops the event; **connection:** `start` twice for the same id joins once; another id replaces the channel and the older channel's callbacks are ignored (generation); `online` while not live → the channel is replaced once and `resync` is emitted once it is live; `online` and `visible` in the same tick → **one** revival; visible after ≤ 2 s away while live → nothing, after > 2 s → `resync`; a revival followed by the new channel's cold start within the skip window → **no second** `resync`; `stop` → `idle`, channel closed, further events ignored; one throwing listener does not stop the others.
